# /doc-check：那次运行对不对

要检查的会话：$ARGUMENTS

只查"由文档生成"的部分，因为有原文才有标准可以对照。内置和插件 skill（如 `/simplify`、`/code-review`、浏览器）不查。

`$D` 指本 skill 的目录（加载时给出的 Base directory），里面的 `timeline.py` 负责读会话记录。`$O` 指当前会话 scratchpad 目录下的 `doc-check-<会话 id 前 8 位>`（没有 scratchpad 就用 `/tmp/doc-check-…`）。

## 步骤

**1. 找会话**：去掉参数前面的"会话："，运行 `python3 $D/timeline.py find "<剩下的部分>"`。
- 没找到：告诉用户，请他给会话 id 或换个词。
- 找到多个：列出来让用户选。标了"里面跑过 /doc-check"的一般是检查会话本身。
- 被检查的不能是当前会话：自己查自己只会自我确认。

**2. 导出**：`python3 $D/timeline.py dump <会话 id> $O`，得到三类文件：
- `timeline.md`：一行一个事件，用 `#n` 编号。
- `agent-*.md`：每个 subagent 的时间线。
- `summary.json`：用到的 skill（含解开软链接后的真实目录）、agent（含定义文件）。

general-purpose agent 的 prompt 如果让它"读某个 agent 定义来扮演"，算作那个 agent 的替身。同一类型 agent 先报错、再换成替身的，记下来，第 5 步要判断。

**3. 找原文**：对每个有目录的 skill 和有定义文件的 agent，按下面的顺序找它依据的文档，找到就停：
1. 自己目录里：SKILL.md、步骤文件或 agent 定义里写明的文档路径或出处标记（如 `〔指南 x.x〕`）。知识库型 skill 的 `references/` 目录本身就是原文。
2. 往上到项目或仓库根目录：`AGENTS.md`、`CLAUDE.md`、`README.md` 里写的"方法论来源 / 依据 / 来源"。
3. 记忆：`~/.claude/projects/*/memory/*.md` 里提到这个 skill 名或它所在目录的条目。
4. 都没找到：这个 skill 可能不是由文档生成的，也可能只是没记来源。把这类 skill 一次性列给用户，问有没有原文路径；用户说没有就跳过。

依据同一份原文的 skill 和 agent 合成一组，例如 /pre-pr、verifier、risk-classifier 同属审查流程。之后一组一组查。

**4. 读**：每组读三样东西，只读和这次运行有关的部分。
- **原文**：读相关章节。知识库型 skill 只读这次会话实际用到的那几个文件。
- **skill**：读 SKILL.md、这次实际跑到的步骤文件、agent 定义。同时记下有意偏离，包括出处标成 `〔系统设定〕` 之类的，以及项目文档或记忆里写明"用户定的"。
- **会话**：读时间线里这组 skill / agent 被调用前后的范围，以及对应 agent 的时间线。时间线长就按编号分段读。会话写出的文件（时间线里 Write / Edit 的路径）如果还在，可以读来核对；如果它在会话之后被改过，要注明。

**5. 判断**：只针对这次运行实际走到的部分，看三类问题。
- **执行偏离 skill**：
  - 步骤跳过、顺序错、关卡被绕过。
  - 说"跑过了 / 通过了"，但时间线里没有对应的命令和结果。
  - 该停下来问用户的地方没问。
  - 该用的 agent 没用，或换了替身。
  - 该写的文件没写。
  - 工具出错后没处理就继续往下做。
- **skill 偏离原文**：这次用到的那部分 skill 和原文不一致，或者原文要求的东西 skill 里没有。有意偏离不算问题，只在"已核对"里注明。
- **结论不符原文**：这次产出的结论、数字、规则说法和原文对不上。

每条问题要有三处证据：会话位置（`#n` 加一句原话）、skill 位置（`文件:行`）、原文位置加一句短引。凑不齐的放进"无法判断"，不要猜。风格、措辞这类不影响结果的不报。

**6. 汇报**：直接回复，不写文件。
- **第一句给数量**：`检查了 <几组>，发现 N 个问题（执行偏离 a、skill 偏离原文 b、结论不符 c）`。没问题就直说"没发现问题"。
- **检查了什么**：每组列出 skill / agent 和原文路径。没查的（内置、插件、找不到原文的）一行带过。
- **问题**：按影响排序，先"重要"（结果错了、关卡被绕过、结论会误导），再"次要"。每条写：类型｜会话位置｜skill 位置｜原文位置和短引｜影响。
- **照做了的关键步骤**：列几条，每条带 `#n`，让用户知道查到了哪里。
- **无法判断**：会话记录里看不到的部分（例如命令行内部做了什么），说明缺什么证据。

## 规矩

- **只读**：不改被检查的 skill、agent、会话产出和仓库，不重跑那次流程，不生成测试。用户要修，另起一件事。
- **不派 subagent**：这个会话本身就是独立于被检查会话的新上下文。
- **两个标准分开用**：原文、skill、会话三方说法不一致时，判断"对不对"以原文为准，判断"照没照做"以 skill 为准，两类问题分开报。
