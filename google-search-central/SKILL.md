# Google 搜索中心知识库

知识库在本 skill 目录的 `references/` 下，按官方文档目录拆分为 166 个 Markdown 文件。完整目录见 `references/README.md`。

## 使用方式

1. 根据需求，先用下方「快速定位」找到相关文件；找不到时读 `references/README.md` 目录，或在 `references/` 下用 Grep 搜关键词（如 `hreflang`、`"@type": "Product"`、`X-Robots-Tag`）。
2. 只读与当前需求相关的文件，不要整目录读取。结构化数据文件较大，可先 Grep 定位到「必需属性」「建议属性」「示例」等小节再读。
3. 按文档中的规则和示例实现代码；文档中标注的必需项、限制条件、禁止做法必须遵守。
4. 说明实现依据时，引用对应文件路径。

## 审查或修复整个网站

用户只说"修复/审查这个项目"、没指定哪一项时，读本 skill 目录下的 `checklist.md`，按其中的规则逐项检查，并按它规定的表格输出全部 21 项，不能只挑部分查。

**与 claude-seo 配合**：已有 claude-seo 的审计报告时，本知识库负责判断和修复，不重复检测：
- 把报告里的每条发现对应到清单的某一项，再对照依据文件，分为"必须改 / 建议 / 不用管"；
- claude-seo 报出、但 Google 文档没有要求的项（例如 llms.txt），分类为"不用管"或"建议"，并注明"非 Google 要求"；
- claude-seo 的检测数据（渲染结果、Core Web Vitals、sitemap 校验）直接作为清单的证据；
- 清单中 claude-seo 报告没有涉及的项，由本知识库自己查。

**第三方工具的提示**（AITDK、各类 GEO 评分等）：先对照 `03-SEO 基础知识/08-针对第三方 SEO 工具和建议的指南.md` 和 `03-SEO 基础知识/04-生成式 AI 基础知识/01-针对生成式 AI 进行优化.md`，再决定改不改。例如 Google 明确说会忽略 llms.txt，生成式 AI 搜索也不需要结构化数据；按英文"词数""字符数"算出的长度提示不适用于中文。

## 向 Search Console 提交

修复完成后，如果需要提交到 Google，例如请求将某个网址编入索引或重新抓取、提交或重新提交 sitemap、在报告里点"验证修复"、移除网址，就用用户自己的浏览器去做，也就是 Claude in Chrome（`mcp__claude-in-chrome__*`）。不要只写一句"请到 Search Console 手动提交"就结束。依据：`04-抓取和编入索引/06-抓取工具管理/01-请求 Google 重新抓取您的网址.md`。

1. 先确认改动已经上线：用线上网址检查新内容确实生效，例如新的 favicon 链接或新的状态码。还没部署就先不提交，告诉用户部署后再提交。
2. 先读 `anthropic-skills:chrome-browser` skill，再按它的说明一次性加载 Chrome 工具，然后在新标签页打开 `https://search.google.com/search-console`，选与站点域名对应的资源。
3. 只提交本次改动涉及的网址：受影响页面用网址检查工具，页面多就提交 sitemap。单个网址的提交有配额，同一个网址重复提交不会更快。
4. 点最后的"请求编入索引"或"提交"之前，在对话里用一句话说明要提交到哪个资源、提交哪个网址，等用户确认后再点。之前的导航和填写不用问。
5. 遇到这些情况就停下，告诉用户并让用户自己处理：没有登录（不要代填账号密码）、没有该资源的所有者或完整权限、配额用完、出现验证码。
6. 提交后汇报结果，例如"已请求编入索引"或 sitemap 状态，并说明抓取可能要几天到几周。
